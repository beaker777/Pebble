从技术上来讲, MySQL 是支持存储图片的, 可以使用 `Blob` 系列的数据类型来存储图片的二进制数据.

但是在实际生产中, 我不建议使用 MySQL 来存储图片, 主要出于以下三点:

## 严重影响数据库性能

数据库的 Buffer Pool 是很宝贵的资源, 在数据库存储大量图片会导致原本的热点数据被挤出 Buffer Pool.

进而导致磁盘 IO 大量增加, 极其影响数据库性能.

## 增加运维难度和成本

在 MySQL 中保存图片会导致占用的空间膨胀 (从 GB 膨胀到 TB), 这会导致备份和恢复的速度变得极慢.

一旦数据库崩溃, RTO (Recovery Time Objective) 将无法保证.

## 架构耦合, 无法加速

图片存储在数据库中, 前端读取时必须经过应用服务器, 增加了后端负载. 同时难以使用 CDN 进行加速.

## 最佳实践

最佳实践是 MySQL 保存图片的 URL, 图片存储在 OSS 或分布式文件系统 (MinIO) 中.

成本低的同时速度还很快.

> CDN (Content Delivery Network) 会在源站的基础上在全国各地建立分站用于缓存.
> 
> 当用户请求的时候会去最近的分站查询数据, 如果分站缓存了需要的数据就直接返回, 速度很快. 
> 只有分站不存在数据的时候才会去源站请求数据, 之后缓存到分站.
> 
> 使用 MySQL 保存图片, 配合 CDN 加速, 如果遭遇恶意随机参数刷缓存, 会导致请求大量回源. 可能造成数据库和业务瘫痪.
