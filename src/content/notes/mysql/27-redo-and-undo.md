Redo Log 和 Undo Log 是保证 MySQL 事务 ACID 特性的两大基石, 它们的区别主要体现在三个方面.

## 对应的 ACID 特性和功能不同

- Redo Log 主要用于数据库崩溃后恢复. 它保证了事务提交的时间不会因为数据库宕机而丢失, 保证了事务的 **持久性**.

- Undo Log 主要用于 MVCC 和事务回滚. 它保证了事务执行异常时可以撤销操作, 保证了事务的 **原子性**.

## 记录的内容形式不同

- Redo Log 记录的是 **物理日志**, 比如 `在第 n 页, 偏移量为 x 的位置写入 y`.

- Undo Log 记录的是 **逻辑日志**, 它会记录 SQL 操作和旧的历史数据, 回滚时根据操作类型逻辑的将数据还原.

## 写入方式与生命周期不同

- Redo Log 是 **循环写入** 的, 空间固定, 写满后从头开始覆盖.

- Undo Log 是 **追加写入** 的, 当事务提交后 MVCC 不需要该 Undo Log, 后台线程会将日志回收.

> 所谓 Undo Log 保存反向 SQL 的说法并不准确.
> 
> 实际上 Undo Log 会保存 **操作类型 + 旧版本数据**, 根据操作类型回滚.
> 
> MVCC 也会使用历史数据作为版本链.
