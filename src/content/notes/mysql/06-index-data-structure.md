MySQL 选择使用 B+ 树来保存索引主要是出于 **减少 IO 次数** 和 **优化范围查询** 的考虑, 可以通过对比其他数据结构来更好地说明这一点.

## 红黑树

红黑树的节点度数过小, 导致数据量大的时候红黑树高度过高.

而 MySQL 的索引是保存在磁盘中的, 树得高度越高磁盘 IO 次数越多, 导致性能下降.

## Hash

Hash 的单点检索速度是最快的, 但是 Hash 结构不支持范围查询, 排序等操作.

## B 树

虽然 B 树也解决了树高, 但是 B+ 树相比 B 树有两个优点:

- 非叶子节点不保存数据: B+ 树的叶子节点只保存索引键, 不保存数据, 使得同样大小的磁盘页能容纳更多数据, 进一步减少了 IO 次数.

- 叶子节点使用链表连接: B+ 树的叶子节点通过链表连接, 方便进行范围查找和排序操作, 效率远高于 B 树的中序遍历.
