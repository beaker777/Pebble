在 MySQL 中推荐使用自增 ID, 不推荐使用 UUID, 这主要是出于 **性能** 和 **存储空间** 两方面的考虑.

## 性能

- 自增 ID 是高效的顺序写, 不会出现页分裂的情况.

- UUID 是乱序的, 经常会写入已满的数据页中间, 触发页分裂. 导致产生大量的磁盘 IO 和数据碎片化.

## 存储空间

- 使用 `BigInt` 作为自增 ID 只占 8B, UUID 通常占 32B 甚至更多.

- InnoDB 辅助索引存储的是主键, 主键过大会导致辅助索引膨胀, 占用磁盘和内存空间.

## 使用雪花算法的场景

在分布式场景下, 自增 ID 无法保证全局唯一, 且容易泄露数据量. 此时雪花算法就成为了最佳选择.

由于雪花算法根据时间戳生成 ID, 所以使用雪花算法既满足全局唯一的要求又是自增的, 可以保留顺序写入索引的性能优势. 是分布式场景的最佳选择.
