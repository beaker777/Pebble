MySQL 在逻辑架构上采取了分为上下两层的设计, 分别对应 **server 层** 和 **存储引擎层**.

## Server 层

- 主要包含 **连接器** (建立客户端到 MySQL 的连接), **分析器** (词法和语法分析), **优化器** (生成执行计划), **执行器** (调用存储引擎层的 API 接口).

- 所有的 **内置函数**, **视图** 等跨引擎功能都在该层实现.

## 存储引擎层

存储引擎层的架构是 **插件式** 的, 主要负责实现数据的存储与读取.

- 一方面 Server 层通过 **调用接口** 的方式和存储引擎层交互, 不感知底层的具体实现.

- 另一方面, 我们可以根据需要选择不同的存储引擎, 比如支持事务和行锁的 `InnoDB`, 不支持事务但读取速度快的 `MyISAM`.
