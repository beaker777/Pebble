走索引只是减少了扫描的行数, 最终的执行时间还受其他因素影响, 主要有以下因素:

## 回表代价过高

当索引的 **区分度** 很低, 或查询出的数据量过多就会产生大量随机磁盘 IO.

由于全表扫描做的是顺序磁盘 IO, 此时走索引的性能可能反而比全表扫描还差.

## 深分页

当遇到了深分页问题时, 需要对 offset + size 条数据全部进行回表再抛弃前 offset 条, 造成大量无用的磁盘 IO.

## 锁竞争

可能 SQL 执行的速度很快, 但目标数据行被其他事务锁定 (如行锁), 只会导致 SQL 的执行时间被迫拉长.

## 系统抖动问题

如果 buffer pool 空间不足需要置换页面, redo log 写满需要刷盘, 这些磁盘 IO 操作会阻塞查询 SQL.
