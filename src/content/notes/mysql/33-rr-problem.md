title: 可重复读级别下, MySQL 彻底解决幻读了吗 ?

MySQL 在很大程度上解决了幻读问题, 但并没有 100% 的解决. MySQL 采取两种机制来解决:

- 对于 **快照读**: 事务启动时生成一个 ReadView 后续所有的查询都是基于这个视图的, 不会读取到其他事务插入的数据.

- 对于 **当前读**: InnoDB 通过加临键锁的方式来解决幻读问题, 阻止其他事务在空隙中插入数据.

在一种特殊情况下, 仍然会触发幻读问题:

- 事务先执行一次查询操作.

- 另一个事务插入了一条数据.

- 如果对新插入的数据执行一次 Update, 就会导致原本在快照读中查询不到的数据出现了. 也就是 **幻读**.

> 快照读是指普通地查询语句, 当前读指 Select ... For Update, Delete , Update 之类的 SQL 语句.
> 
> 快照读不需要加锁, 根据 MVCC 读取快照中的历史数据. 当前读必须加锁, 会读取到最新的历史版本.
