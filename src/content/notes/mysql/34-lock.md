MySQL 中的锁机制非常丰富, 可以通过三个方面来分析:

## 锁粒度

- 全局锁: 锁住整个数据库实例, 通常用于数据库备份.

- 表级锁: 包括显式的表锁和隐式的 MDL. 在 Select 时会自动申请 MDL 读锁, 如果有后续的事务要修改表的字段申请 MDL 写锁. 
此时如果获取不到 MDL 写锁会导致后续的所有 Select 都被阻塞, 让服务彻底瘫痪.

- 行级锁: 这是 InnoDB 的核心特性, 它可以锁住单行记录.

## 互斥属性

根据互斥属性可以分为共享锁和排他锁, 为了在加表锁的时候快速判断, MySQL 还引入了意向共享锁和意向排它锁.

## InnoDB 特有的锁算法

在 RR 级别下, InnoDB 的锁有三种实现:

- Record Lock: 行锁只会锁住一行记录.

- Gap Lock: 间隙锁会锁住索引之间的间隙, 用于防止幻读.

- Next-Key-Lock: 临键锁是 **行锁 + 间隙锁**, 是 InnoDB 默认的加锁单位.
